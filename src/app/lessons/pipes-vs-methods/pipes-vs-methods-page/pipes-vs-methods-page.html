Pipes vs component methods

Both examples call the same filtering function and display the same result. The difference is how Angular evaluates and caches the template expression.

Try the reference-change experiment

{{ mutationMessage() }}

Pure pipe

lessons() | lessonFilter: query()

    @for (lesson of lessons() | lessonFilter: query(); track lesson) {
  • {{ lesson }}
    • } @empty {
  • No matching lessons
    • }

Angular caches the result while the array reference and query value remain unchanged. This is efficient, but hidden in-place mutations are intentionally not detected.

Component method

filteredWithMethod()

    @for (lesson of filteredWithMethod(); track lesson) {
  • {{ lesson }}
    • } @empty {
  • No matching lessons
    • }

Angular invokes the method whenever it checks this view. It can observe mutated contents, but it may repeat filtering when unrelated state changes.

Choose a pipe when…

  • The operation formats a value for display.
  • The transformation is reusable across templates.
  • The function is pure: the same inputs always produce the same output.

Choose a method when…

  • The work is trivial and specific to one component.
  • It handles an event rather than calculating displayed data.
  • Repeated evaluation has no meaningful performance cost.

Choose computed() when…

  • The value derives from signal state.
  • TypeScript and the template both need the result.
  • You want memoization based on tracked signal dependencies.
Avoid impure pipes by default. Setting pure: false detects internal array/object mutations, but it also runs the pipe on every check—giving up the main performance advantage. Prefer immutable updates that create new references.
