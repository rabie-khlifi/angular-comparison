Angular testing fundamentals

The two working counters below are also exercised by the adjacent Vitest specification.

Modern signal state

The test can call count.set(), wait for stability, and assert rendered output.

Classic property state

The same user-facing behavior is tested through a click. Regular properties still work.

Arrange, act, wait, assert

  1. Arrange: configure TestBed and create a component fixture.
  2. Act: change an input/state value or trigger a real DOM event.
  3. Wait: use await fixture.whenStable() for scheduled rendering.
  4. Assert: verify visible behavior rather than private implementation details.

Old vs current testing habits

Older zone-based tests frequently called fixture.detectChanges(), used fakeAsync()/tick(), and manually coordinated change detection.

Modern zoneless tests favor normal async functions and whenStable(). This follows the user interaction → scheduled render → assertion lifecycle and is less coupled to implementation timing.

TestBed and ComponentFixture are not obsolete: they remain the standard Angular test environment. Vitest is the runner providing describe, it, and expect.

Prefer testing public behavior: text, accessible roles, emitted events, navigation, and service contracts. A test that reaches into private methods may pass while the actual UI is broken.
