Lesson 9

Component providers vs providedIn: root

The injection token can be identical while provider placement changes instance identity, sharing, and lifetime.

Root scope: one shared fallback instance

Both blue consumers display the same instance ID. Incrementing either updates both counts.

Provider scope existed before signals

Signals only make the counter value reactive; they do not create or share the service. The same injector rules apply when a service stores a plain property, exposes a BehaviorSubject/Observable, or has no state at all. 

// All three use the provider's lifetime:
count = 0;                         // plain property
count$ = new BehaviorSubject(0);  // pre-signals reactive state
count = signal(0);                // modern reactive state

Changing the state API does not change instance identity. Moving the provider between root, route, component, or directive scope does.

Component scope: one instance per host subtree

Each purple component has a different ID and isolated count because each host declares its own provider.

How Angular resolves inject(ScopedCounter)

  1. Start at the requesting element. Check its ElementInjector.
  2. Walk through parent elements. The first matching token wins.
  3. Search environment injectors. Route and root providers are checked when no element provider matched.
  4. Fail if absent. Angular throws a provider-not-found error unless the injection is optional.

The purple component finds its own provider at step 1, so the root instance is shadowed. The blue component reaches the root environment provider at step 3.

Concern providedIn: root Component providers
Instances One per root environment injector One per component instance declaring the provider
Available to Application-wide unless shadowed Component and descendant subtree
Lifetime Usually application lifetime Destroyed with providing component
Typical use API clients, auth, global configuration, shared stores Isolated editors, wizard state, per-widget coordination
Tree-shakable automatic provider Yes Manual provider entry

Provider syntax

// Automatic root provider on the service
providedIn: 'root'

// Manual provider on a component
providers: [ScopedCounter]

// The shorthand represents an object using:
provide: ScopedCounter
useClass: ScopedCounter

A component provider can override even a root-provided service. Descendant components inherit that nearer instance unless they declare another override.

Do not add a service to every component's providers array by habit. That silently creates multiple instances and often explains why “shared” state does not stay shared.
