Classic creation order

  1. constructor: TypeScript creates the class and Angular can inject dependencies.
  2. ngOnChanges: Angular supplies initial input values.
  3. ngOnInit: one-time initialization after initial inputs.
  4. ngAfterViewInit: the component view and view queries are ready.
  5. ngOnDestroy: final cleanup immediately before removal.
Need Classic API Modern option
React to input changes ngOnChanges(SimpleChanges) or input setter input() consumed by computed()/effect()
One-time initialization ngOnInit Field initialization, constructor setup, or keep ngOnInit
Query the view @ViewChild after ngAfterViewInit viewChild() signal plus a render callback
DOM work after rendering ngAfterViewInit/ngAfterViewChecked afterNextRender/afterRenderEffect
Cleanup ngOnDestroy DestroyRef.onDestroy()
Hooks are still valid. Modern APIs are composable alternatives, not a blanket replacement. Use computed() for derived values, reserve effect() for real side effects, and keep lifecycle work small so change detection remains predictable.
