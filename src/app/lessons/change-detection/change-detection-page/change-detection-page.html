What can trigger an OnPush check?

  • A bound input receives a different value/reference according to Angular's comparison.
  • An event listener runs inside the component or its view subtree.
  • A signal read by the template changes.
  • AsyncPipe receives a new Observable/Promise value.
  • Code explicitly calls markForCheck() or detectChanges().

Before signals

OnPush applications used immutable input updates, template events, AsyncPipe, and ChangeDetectorRef.markForCheck(). RxJS stores commonly emitted new immutable objects that AsyncPipe delivered to the view.

With signals

When an OnPush template reads a signal, Angular tracks that dependency. Calling set() or update() notifies Angular to check that view. Signals reduce manual marking, but input objects should still be updated immutably.

Concern Default OnPush
Checking behavior Checked whenever its ancestor traversal reaches it Can skip the subtree until a known trigger marks it
Same-reference mutation Often appears to work because the view is checked Can remain stale because input identity did not change
Best state style Immutable updates still improve predictability Immutable inputs plus signals/AsyncPipe
OnPush is not “check only once.” It means Angular may skip a clean subtree. Do not mutate inputs and then depend on an unrelated click to reveal the change; replace references or use a reactive source that explicitly notifies Angular.
