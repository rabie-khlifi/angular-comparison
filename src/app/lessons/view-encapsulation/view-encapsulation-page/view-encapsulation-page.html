Emulated vs None vs Shadow DOM encapsulation

All three components have their own stylesheet. Encapsulation controls whether those rules are rewritten, global, or placed inside a native browser shadow root.

Page-level .global-theme rule: it can enter Emulated, but not Shadow DOM.

I live outside NoneCard, but its unscoped stylesheet still styles me.

Inspect the DOM in browser DevTools

  • Emulated: Angular adds generated attributes to elements and rewrites component selectors to include those attributes.
  • None: the stylesheet appears as normal global CSS with no scoping.
  • ShadowDom: the custom element contains a real #shadow-root managed by the browser.

Before signals and today

View encapsulation has no dependency on signals. Older NgModule components and modern standalone components use the same ViewEncapsulation enum and the same CSS boundaries. Signals decide when reactive state updates a view; encapsulation decides where CSS selectors are allowed to match.

:host styles the component host. :host-context() reacts to an ancestor context but is discouraged for new design systems. Avoid ::ng-deep; it breaks encapsulation and remains only for backwards compatibility.

Default recommendation: keep Emulated for ordinary application components. Use None only for intentionally global rules with carefully prefixed selectors. Choose Shadow DOM when native isolation is worth its theming, projection, testing, and third-party integration tradeoffs.
