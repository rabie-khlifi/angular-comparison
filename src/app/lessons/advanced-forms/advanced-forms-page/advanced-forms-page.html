Signal Forms vs classic Reactive Forms

Modern: Signal Forms

@if (modernForm.username().pending()) { Checking availability… } @for (error of modernForm.username().errors(); track error.kind) { {{ error.message }} } @for (error of modernForm.email().errors(); track error.kind) { {{ error.message }} }

Classic: Reactive Forms

@if (classicForm.controls.username.pending) { Checking availability… } @if (classicForm.controls.username.touched && classicForm.controls.username.hasError('required')) { A username is required. } @if (classicForm.controls.username.hasError('taken')) { The username admin is already taken. } @if (classicForm.controls.email.touched && classicForm.controls.email.invalid) { Enter a valid email address. }

{{ classicMessage() }}

The important difference

Signal Forms: the signal object is your data model. The form tree adds validation and interaction state, and field state is read by calling the field: modernForm.username().pending().

Reactive Forms: FormGroup and FormControl are the form model. Their values/statuses expose Observables, and async validators traditionally return an Observable or Promise.

Reactive Forms are not obsolete. They remain appropriate in existing codebases and mature form libraries. For new Angular 21+ forms, Signal Forms provide typed signal-native state with less manual bridging.
