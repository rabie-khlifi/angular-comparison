Attribute directives modify an existing host. Structural directives control whether template views exist.

What Angular does with the asterisk

<article *appUnless="condition">...</article>

becomes conceptually:

<ng-template [appUnless]="condition">
  <article>...</article>
</ng-template>

Were *ngIf and *ngFor structural directives?

Yes. Angular historically provided these through CommonModule. They use the same structural-directive machinery as our custom *appUnless example.

Legacy built-in directives

*ngIf="isVisible"
*ngFor="let item of items"
[ngSwitch] with *ngSwitchCase and *ngSwitchDefault

NgIf, NgFor, and the NgSwitch family are deprecated since Angular 20. They still exist in Angular 22 for compatibility, but new code should avoid them.

Modern built-in control flow

@if (isVisible) { ... }
@for (item of items; track item.id) { ... }
@switch (value) { ... }

These are compiler-supported template blocks, not directive classes. They need no CommonModule or component import.

Complete legacy *ngIf with else example

This example really imports and runs NgIf. Toggle the condition to make Angular swap between two template views.

Permission granted: the *ngIf "then" view is rendered.
Permission denied: the referenced "else" template is rendered. 
<article *ngIf="hasPermission; else noPermission">
  Permission granted
</article>

<ng-template #noPermission>
  Permission denied
</ng-template>

Why only one * directive per element?

Each asterisk asks Angular to wrap that element in one hidden ng-template. With two asterisks, Angular cannot know which generated template should be outside and execute first. Nesting order changes behavior, so you must write that order explicitly.

Invalid: two structural shorthands compete for one element

<li *ngIf="show" *ngFor="let item of items">
  [item value]
</li>

Correct: use a wrapper to define the order

<ng-container *ngIf="show">
  <li *ngFor="let item of items">[item value]</li>
</ng-container>

The outer condition runs first. Only when true does Angular create the inner template whose *ngFor produces list items. ng-container groups template behavior without adding a real HTML wrapper to the rendered DOM.

Modern equivalent: nested control-flow blocks

@if (show) {
  @for (item of items; track item) {
    <li>[item value]</li>
  }
}

Remember: “one structural directive” means one *... shorthand on a single host element. It does not mean a page can use only one structural directive. Use as many as needed on separate or explicitly nested elements.
