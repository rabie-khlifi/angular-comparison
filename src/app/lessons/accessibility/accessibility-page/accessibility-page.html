Accessibility is more than ARIA

  • Use semantic elements and logical heading order before adding roles.
  • Give inputs labels, images meaningful alt text, and icon-only buttons accessible names.
  • Preserve visible focus, keyboard order, sufficient contrast, zoom, and reduced-motion preferences.
  • Use ARIA only to communicate semantics native HTML cannot express; incorrect ARIA can make a control worse.
  • Test with keyboard, automated checks, and at least one screen reader—automation cannot judge everything.
Old mistake vs modern practice: a clickable <div> needs tabindex, keyboard handlers, role, and state attributes. A native <button> already has the correct semantics. For complex widgets such as tabs, listboxes, trees, or grids, install and use Angular Aria rather than hand-writing their keyboard model.
