Lesson 6

Inputs vs model inputs

input() gives a child read-only data from its parent. model() creates a writable input designed for two-way binding.

One-way input

Parent controls:

Parent value: {{ readonlyRating() }}

Two-way model input

Parent value changes from the child's buttons: {{ editableRating() }}

Before signals: one-way @Input

Parent controls:

Plain parent property: {{ classicRating }}

@Input() vs input()

// Classic decorator API
@Input({ required: true }) rating!: number;
get stars() { return formatStars(this.rating); }

// Modern signal API
rating = input.required<number>();
stars = computed(() => formatStars(this.rating()));

Both are one-way parent-to-child inputs. A classic input is an ordinary property and commonly reacts through a setter or ngOnChanges. A signal input is read-only reactive state that composes directly with computed() and effect().

What banana-in-a-box expands to

The model declaration rating = model.required<number>() creates an input named rating and an output named ratingChange. 

<app-editable-rating [(rating)]="editableRating" />

is shorthand for the input + output pair:

<app-editable-rating
  [rating]="editableRating()"
  (ratingChange)="editableRating.set($event)"
/>
Concern input() model()
Direction Parent → child Parent ↔ child
Child can write? No; InputSignal is read-only Yes; ModelSignal has set()/update()
Implicit output? No Yes: input name + Change
Input transforms? Supported Not supported
Typical use Configuration and display data A value the child is responsible for editing

Choosing correctly

Prefer input() by default because one-way data flow makes ownership explicit. Use model() when editing the value is genuinely part of the child's public purpose, such as a custom form control, slider, date picker, or reusable counter.

Do not use model() merely so a child can change arbitrary parent state. For actions rather than value synchronization—save, delete, opened, submitted—use a named output, which is the next lesson.

Important: two-way binding does not create shared global state. It is syntax connecting one child input/output pair to one parent expression or writable signal.
