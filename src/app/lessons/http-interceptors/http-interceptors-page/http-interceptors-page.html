Classic interceptor

@Injectable()
class AuthInterceptor implements HttpInterceptor {
  intercept(req, next) {
    return next.handle(req.clone({ ... }));
  }
}

Registered through the multi-provider token and enabled with withInterceptorsFromDi().

Functional interceptor

const authInterceptor: HttpInterceptorFn =
  (req, next) => next(req.clone({ ... }));

Registered explicitly with withInterceptors(); preferred for predictable ordering and simpler composition.

Good interceptor responsibilities

  • Attach authentication, correlation, locale, or version headers.
  • Centralize logging, timing, caching policy, or consistent error translation.
  • Use HttpContextToken for per-request metadata that should not reach the backend.

Do not hide feature-specific recovery in a global interceptor. A component or service should decide whether to show a fallback, retry, redirect, or let the error continue.

Requests are immutable. Clone before modifying headers or options. Interceptors can run again during retries, so avoid mutating request/response bodies in place.
