Signals vs regular properties

Both store values. Signals additionally notify reactive consumers and track derived dependencies.

Angular reactive state

Signal

Count: {{ signalCount() }}

Computed double: {{ signalDouble() }}

computed() cannot become stale through a forgotten assignment; its dependency is tracked automatically.

How the regular-property approach works

  1. The class stores the raw number directly in regularCount.
  2. A method assigns a new value with normal TypeScript syntax.
  3. Angular must run change detection before the template reads the property again.
  4. Any separately stored derived value must be updated manually on every write path.

The property has no knowledge of its readers. It cannot announce “I changed.” Angular may still check it because another event—such as this page's button click—scheduled a template check.

Good uses

  • Constants and configuration that do not change.
  • Temporary values used only inside one method.
  • Non-reactive implementation details that no template or derived state observes.

How the signal approach works

  1. signal(0) creates a writable reactive value.
  2. The template calls signalCount(), registering itself as a consumer.
  3. set() or update() changes the value and notifies consumers.
  4. computed() is invalidated and recalculates lazily when read again.

This explicit dependency graph lets Angular know which view consumed which state. It is particularly useful with OnPush components and for derived state shared by several consumers.

Good uses

  • Mutable state displayed by a template.
  • State used by one or more computed() values.
  • State exposed by a service to multiple reactive consumers.

Three ways to represent “double”

Copied property: regularDouble
Fast to read, but it duplicates state. Every code path that changes the count must also change the double. The red button demonstrates the resulting stale-state bug.
TypeScript getter: regularDoubleGetter
Always derives from the latest count, so it cannot drift. However, Angular can call the getter during every relevant change-detection pass; Angular does not cache its result.
Computed signal: signalDouble
Derives from the latest signal, records that dependency, and caches its result. It is invalidated only when a dependency changes and recalculates only when a consumer reads it.

What signals do—and do not—do

Concern Regular property Signal
Read count count()
Write count = 10 count.set(10)
Update from old value count += 1 count.update(value => value + 1)
Notify reactive consumers No built-in notification Yes
Derived value Getter or manual synchronization Memoized computed()

Common signal mistakes

Forgetting parentheses when reading

signalCount is the signal object; signalCount() is its value.

Assigning directly

Do not write signalCount = 10. Use signalCount.set(10).

Mutating an object in place

Changing a property inside the current object does not call the signal setter. Return a new object from update() so consumers are notified.

Using an effect for derived state

Prefer computed() for values derived from other signals. Effects are primarily for synchronizing with non-reactive systems, not copying state between signals.

Important: a regular property still updates on this page after a click because Angular runs change detection for template events. Signals do not replace every property. Use plain properties for non-reactive constants or temporary implementation details; use signals for state whose changes should update reactive consumers.
