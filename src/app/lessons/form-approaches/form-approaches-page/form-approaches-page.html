Lesson 10

Template-driven vs reactive vs signal forms

The three forms collect and validate the same name and email. Their main difference is where the form model and rules live.

Three mental models

Template-driven

The template declares controls and validators. Angular discovers them through directives and builds an internal form model.

Reactive

TypeScript explicitly constructs FormControl/FormGroup objects. The template connects elements to that existing model.

Signal Forms

A signal owns the domain model. form() derives a typed field tree, and schema rules plus FormField connect validation and controls.

Concern Template-driven Reactive Signal Forms
Import FormsModule ReactiveFormsModule FormField

Binding [(ngModel)] formControlName [formField]

Change stream Directive state valueChanges/events Observables State signals
Best fit Small, simple legacy forms Existing complex reactive-form code New forms in Angular 21+

How to choose

Template-driven: concise for a small form, but behavior becomes spread through HTML and scales poorly when rules become dynamic.

Reactive: mature, explicit, testable, and powerful for dynamic groups and arrays. Keep it for established codebases already invested in this model.

Signal Forms: preferred for new forms in this Angular 22 project. It offers typed signal state, schema rules, field metadata signals, and direct integration with modern Angular reactivity.

Signal Forms rules that prevent common mistakes

  • Initialize fields with non-null values such as empty strings, zero, false, or empty arrays.
  • Call a field to access state: profileForm.email().errors().
  • Do not add value, disabled, readonly, min, or max to a control using [formField]; express those through the model/schema APIs.
  • The callback passed to submit() is async and runs only for a valid form.
Do not rewrite a stable form only for fashion. Choose based on Angular version, existing architecture, complexity, team knowledge, and migration cost. For new Angular 22 work, start with Signal Forms.
