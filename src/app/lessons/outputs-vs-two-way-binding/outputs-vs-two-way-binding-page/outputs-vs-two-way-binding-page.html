Angular data binding, outputs, and two-way binding

Angular has four fundamental binding forms. Outputs power custom event binding, while two-way binding combines a value binding with a change event.

The four data-binding types

1

Interpolation: double curly braces

{{ interpolationMessage() }}

Direction: component → view. Best for text content and string interpolation.

2

Property binding: [property]="expression"

Direction: component → view. Preserves types rather than converting every value to text.

3

Event binding: (event)="statement"

Handled clicks: {{ eventCount() }}

Direction: view → component. Responds to native or custom events.

4

Two-way binding: [(target)]="state"

Signal parent: {{ signalLearnerName() }}

Property parent: {{ learnerName }}

Direction: component ↔ view. Combines property and event binding.

Modern model() text-input expansion

<app-model-text-input
  [(value)]="signalLearnerName"
/>

is conceptually:

<app-model-text-input
  [value]="signalLearnerName()"
  (valueChange)="signalLearnerName.set($event)"
/>

Inside the child, value = model('') supplies both sides of this contract. The child renders a native text input and calls value.set(...) for every input event.

Property binding is not always attribute binding

HTML attributes initialize elements, while DOM properties represent their live state. [disabled]="false" sets the boolean DOM property to false. The literal attribute disabled="false" still disables a button because that boolean attribute's presence matters, not its text.

  • [value], [disabled], and component inputs bind properties.
  • [attr.aria-label] explicitly writes an HTML attribute.
  • [class.active] and [style.width.px] are specialized class/style bindings.

Component two-way binding: old and new APIs

The parent template can use the same banana-in-a-box syntax for both. The difference is how the child declares and updates the contract.

Modern: model signal

Modern parent signal: {{ notificationsEnabled() }} 

enabled = model(false);

toggle() {
  this.enabled.update(value => !value);
}

Classic: decorator input/output pair

Classic parent property: {{ legacyNotificationsEnabled }} 

@Input() enabled = false;
@Output() enabledChange = new EventEmitter<boolean>();

toggle() {
  this.enabled = !this.enabled;
  this.enabledChange.emit(this.enabled);
}

The classic syntax expansion

<app-legacy-notification-toggle
  [(enabled)]="legacyNotificationsEnabled"
/>

is shorthand for:

<app-legacy-notification-toggle
  [enabled]="legacyNotificationsEnabled"
  (enabledChange)="legacyNotificationsEnabled = $event"
/>

The naming convention is the mechanism: an input called enabled plus an output called enabledChange. Angular recognizes the pair and allows [(enabled)]. model() did not invent a different runtime contract; it provides the same contract with less declaration and a writable signal API.

How outputs and two-way binding fit the four types

Output event

<app-profile-editor
  (saved)="handleSaved($event)"
/>

This is event binding. The parent runs arbitrary logic; nothing is assigned automatically.

Two-way value

<app-notification-toggle
  [(enabled)]="notificationsEnabled"
/>

Angular connects [enabled] and (enabledChange) as one synchronization contract.

What [(ngModel)] combines

<input [(ngModel)]="learnerName" />

is shorthand for:

<input
  [ngModel]="learnerName"
  (ngModelChange)="learnerName = $event"
/>

NgModel is a directive supplied by FormsModule. Native inputs do not have a built-in ngModel property; the directive supplies the input and output that create this contract.

Concern Output Two-way binding
Meaning An event happened One value changed
Child API output<T>() model<T>() or input/output pair
Syntax (saved)="handler($event)" [(enabled)]="state"
Parent behavior Explicit handler decides Assignment/signal synchronization
Best names saved, closed, selected enabled, value, rating

Output details worth remembering

  • Angular custom outputs do not bubble through the DOM like native click events.
  • Output names are case-sensitive; avoid collisions with native DOM events.
  • Prefer saved, not onSaved.
  • output() returns an OutputEmitterRef, not an RxJS Observable.
  • The legacy @Output() new EventEmitter() remains supported but is not preferred for new code.
Rule of thumb: curly braces display text, square brackets push a value, parentheses listen for an event, and combined [()] synchronizes a value both ways.
