Common pre-signals state pattern

BehaviorSubject: an Observable with current state

A plain Subject represents future events and has no current value. A BehaviorSubject requires an initial value, remembers the latest value, and sends it immediately to each new subscriber. This made it a common choice for Angular service stores before signals.

Follow each update

Signal

input event → set() → computed invalidated → template reads current value

There is no subscription and no debounce in this example. Reading is synchronous.

Observable

input event → next() → debounce → map → emission → AsyncPipe updates view

The subscriber receives values only when the pipeline emits them.

What debounce actually optimizes

It can reduce

  • HTTP requests triggered by rapidly changing search text.
  • Expensive filtering, validation, or data processing.
  • Repeated writes to storage or analytics systems.

It does not reduce

  • Browser input events—the user still produces every event.
  • Writes to the immediate source signal in this pattern.
  • Work that still reads signalQuery() instead of the debounced signal.

Debounce intentionally adds latency. Use it for bursty input before expensive or external work, not for every state update. Button clicks, toggles, and values that must respond immediately usually should not be debounced.

Which should I choose?

Choose a signal for selection state, toggles, counters, component/service state, and synchronous derivations.

Choose an Observable for HTTP/event streams, debouncing, cancellation, retries, websockets, or combining multiple async sources.

Use both when RxJS manages an asynchronous workflow and a signal presents its latest state to Angular UI.

Subscription and cleanup details

  • AsyncPipe subscribes for the template and automatically unsubscribes when its view is destroyed or its Observable reference changes.
  • toSignal() subscribes immediately and normally cleans up with the component's injection context.
  • toObservable() tracks the source signal through an Angular effect and emits after the signal stabilizes. Several synchronous set() calls may become one latest emission.
  • A manual subscribe() gives full control but also gives your code responsibility for teardown; prefer framework-managed consumption when it fits.
Important: an Observable is not simply an “asynchronous signal,” and a signal is not a replacement for RxJS. Their overlap is useful, but their core jobs and lifecycle semantics differ.
