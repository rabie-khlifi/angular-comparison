Route guards vs data resolvers

Guards decide whether navigation may continue. Resolvers obtain critical data before the destination activates.

Guard

  • Runs before activation.
  • Returns allow, block, redirect, Promise, or Observable.
  • Protects navigation UX, not backend security.

Resolver

  • Runs after guards succeed and before activation completes.
  • Supplies values through route data.
  • Delays navigation, so keep critical work small.

Before signals and functional APIs

Older Angular used injectable classes implementing CanActivate or Resolve<T>, constructor injection, and route-data Observables consumed with AsyncPipe. All are demonstrated here.

Modern routes prefer CanActivateFn/ResolveFn, inject(), and optionally bridge route data to signals. The router contract itself is unchanged.

Security rule: never rely on a browser guard to authorize sensitive data or actions. The server must validate every protected request.
